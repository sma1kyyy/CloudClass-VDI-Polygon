☁️ CloudClass: Образовательный облачный полигон

Проект по дисциплине «Технологии виртуализации» — 3 курс, весенний семестр

🏢 8 занятий × 90 мин
👥 Командная работа (3–4 чел)
🎯 Итоговый проект – мини-провайдер VDI


⚠️ Условия выполнения проекта:

Каждая команда получает 3–4 ноутбука с характеристиками: 16 ГБ ОЗУ, 512 ГБ SSD. Ноутбуки выступают в роли физических серверов. Все образы ОС, дистрибутивы и ISO студенты загружают самостоятельно с официальных сайтов. Развертывание выполняется на голом железе или с использованием вложенной виртуализации (по согласованию с преподавателем).

Работа выполняется во время проведения занятий.


🎓 Практическое применение

Учебный центр или ИТ-колледж выдает студентам готовые рабочие окружения (Linux labs, Windows для 1С, Docker-песочницы) на 80+ человек. Проект решает задачу частного облака с низкой стоимостью владения.

✔️ Студенты получают доступ к терминальным сессиям и VDI через браузер (Guacamole)
✔️ Сессии изолированы, профили кочуют между серверами
✔️ Автоматическое масштабирование на Proxmox + FreeBSD


🏗️ Стек технологий

Гипервизор: Proxmox VE 8 (KVM + LXC)
Маршрутизация + Storage: FreeBSD 14 (pf, NFS, haproxy, dummynet)
VDI серверы: Linux (X2Go + MATE) / Windows (RDSH)
Контейнеры: Docker + Portainer + Guacamole + code-server
Мониторинг: Prometheus + Grafana в Docker


🗺️ Логическая архитектура (4 узла на ноутбуках)

🔗 Сетевые зоны:
   VLAN 10 – управление
   VLAN 20 – VDI трафик
   VLAN 30 – Docker/Pod
   VLAN 40 – NFS/iSCSI

Каждый ноутбук выполняет строго свою роль.


💻 Распределение нагрузки на ноутбуки (16 ГБ RAM, 512 ГБ SSD)

🔹 Ноутбук 1 (Router/Storage)
   - FreeBSD 14 (2 vCPU, 2GB RAM)
   - NFS / Samba шары
   - pf, dummynet, HAProxy
   - Остальное место – под ISCSI и логи

🔹 Ноутбук 2 (Proxmox)
   - Proxmox VE (хостовая ОС)
   - ВМ: Linux VDI (4GB RAM)
   - ВМ: Windows VDI (6-8GB RAM)
   - Шаблоны и бэкапы на NFS

🔹 Ноутбук 3 (Docker + сервисы)
   - Ubuntu Server 22.04 (хост)
   - Portainer, Guacamole
   - Docker-in-Docker, code-server
   - Prometheus + Grafana

🔹 Ноутбук 4 (опционально / резерв)
   - Доп. VDI или второй Proxmox узел
   - Резервный мониторинг
   - Либо используется для отказоустойчивости

💡 Совет по ресурсам: используйте легковесные Linux VDI (XFCE/Lubuntu) вместо тяжелых окружений; Windows VDI выделяйте не более 6-8 ГБ и отключайте визуальные эффекты.


📅 Поэтапный план работ (адаптирован под 16 ГБ ОЗУ)

Каждая команда ведет репозиторий (Git) с конфигами, скриптами и отчетом. Все ISO-образы скачиваются студентами самостоятельно с официальных источников.


⚙️ Занятие 1. Проектирование сети и установка Proxmox (ноутбук #2)

   - Установить Proxmox VE на выделенный ноутбук (чистая установка поверх Debian/с ISO Proxmox).
   - Настроить мосты: vmbr0 (LAN), vmbr1 (для общения с FreeBSD).
   - Схема адресов: 10.0.0.0/16, VLAN 10 (Mgmt), 20 (VDI), 30 (Docker), 40 (Storage). План адресации.
   - Проверить доступ к веб-интерфейсу Proxmox. Создать первую тестовую ВМ (Debian minimal) с 512MB RAM.

📌 Результат: Рабочий Proxmox на ноутбуке, сформирована документация по IP-плану.


🔧 Занятие 2. FreeBSD – умный маршрутизатор и хранилище (ноутбук #1)

   - Установить FreeBSD 14 на первый ноутбук (2 vCPU выделено из физических, 2GB RAM).
   - Настроить pf (packet filter) – NAT для клиентских сессий, ограничение скорости через dummynet (max 3-5 Mbit на VDI-поток — экономия трафика).
   - Поднять NFS-экспорт для образов ISO (/usr/local/iso) и каталога бэкапов Proxmox.
   - Создать Samba-шару /srv/share для обмена файлами между виртуальными столами.

📌 Результат: FreeBSD является шлюзом сети, файловым сервером, ограничение скорости активно.


🖥️ Занятие 3. Развёртывание базовых ВМ: Linux VDI и Windows VDI (ноутбук #2 Proxmox)

   - Установить Ubuntu 22.04 LTS + X2Go Server + XFCE (легковесный) – выделить 2GB RAM, VirtIO диск.
   - Установить Windows 10 LTSC (или Windows Server 2019) с ролью RDS Host – выделить 6GB RAM, включить virtio драйверы.
   - Интегрировать VirtIO драйверы для дисков и сети внутри Windows.
   - Создать шаблоны (templates) в Proxmox, отключить ненужные службы для экономии памяти.

📌 Результат: Два легковесных образа VDI, доступ по RDP/X2Go.


⚖️ Занятие 4. Терминальный сервер + балансировка на FreeBSD

   - Установить HAProxy на FreeBSD – балансировка RDP-подключений между Linux/Windows VDI.
   - Настроить SSH Jump host (студент заходит на FreeBSD:2222 → переброс в Docker-контейнер).
   - Настроить syslog-сервер (в Docker на ноутбуке #3) для сбора логов всех сессий.
   - Проверить переподключение клиента при отказе VDI (имитация отключения ВМ).

📌 Результат: HAProxy балансирует RDP, логи централизованы.


🐳 Занятие 5. Docker – портал и user-окружения (ноутбук #3)

   - Установить Ubuntu Server 22.04 на третий ноутбук (базовый хост).
   - Развернуть Docker, docker-compose.
   - Запустить Portainer, Apache Guacamole (web-шлюз к RDP/SSH), code-server и Docker-in-Docker (dind) с ограничением ресурсов через --memory="512m".
   - Организовать автозапуск контейнеров через docker-compose.yml.
   - Протестировать доступ через браузер: http://ip-ноутбука3:8080/guacamole → выбор окружения.

📌 Результат: Web-портал для запуска удаленных столов и контейнерной песочницы.


👥 Занятие 6. VDI-кластер и роуминг профилей

   - Смонтировать NFS-шару (FreeBSD) в /home на Linux VDI и в D:\Users на Windows VDI.
   - Настроить автоматический logout сессий через 15 минут бездействия (для экономии ОЗУ).
   - Добавить GPU-ускорение для Linux VDI (virtio-gpu в Proxmox).
   - Проверить roaming: пользователь заходит за разными VDI – видит одни и те же документы.

📌 Результат: Единое пространство пользовательских данных, высокая доступность профилей.


📊 Занятие 7. Мониторинг, логирование и бэкапы

   - Установить Prometheus + Grafana (через Docker на ноутбуке #3), настроить экспортеры: node_exporter, proxmox_exporter (сбор метрик с Proxmox).
   - Создать дашборды: количество активных сессий, загрузка CPU VDI, использование NFS-шары.
   - Настроить автоматический бэкап ВМ через vzdump на NFS FreeBSD (расписание cron раз в день).
   - Реализовать простой HA restart: при падении Windows VDI – Proxmox перезапускает ВМ на том же узле.

📌 Результат: Графана с метриками, политика бэкапов, авто-восстановление сервисов.


🚀 Занятие 8. Интеграция, нагрузочное тестирование и защита проекта

   - Сценарий нагрузки: 3 Docker-контейнера (c ограничением памяти), 2 студента подключаются к Windows VDI, 2 – к Linux VDI.
   - Показать миграцию сессии между VDI-серверами без разрыва через балансировщик (при наличии второго VDI).
   - Сымитировать отказ одного VDI-хоста (выключить ВМ) – время переподключения < 15 секунд.
   - Защита проекта: презентация, демо работы Web-портала Guacamole, сдача docker-compose, ansible-playbook (если есть), pf.conf, скриншоты дашборда Grafana.

🎯 Итог: Полностью работающее «облако на 3-х ноутбуках», готовое к выдаче студенческих окружений.
