## Что мы строим и зачем

### Практическая задача
Учебный центр или ИТ-колледж должен выдавать студентам **готовые рабочие окружения** (Linux-лаборатории, Windows для 1С, Docker-песочницы) на 80+ человек одновременно — без покупки дорогостоящего серверного оборудования и без использования внешних облаков.

### Что получит пользователь (студент колледжа)
- Открывает браузер → заходит на веб-портал (Apache Guacamole)
- Выбирает окружение: Linux-рабочий стол, Windows, или терминал в Docker-контейнере
- Работает полностью через браузер, без установки клиентского ПО
- Его файлы сохраняются и доступны с любого рабочего места (роуминг профилей через NFS)
- Сессия изолирована от других студентов

### Что мы реализуем
```
[Студент с браузером]
        │
        ▼
[Apache Guacamole] ──── веб-шлюз к RDP/SSH (Ноутбук 3)
        │
        ├──► [Linux VDI — XFCE + X2Go] ──── (Ноутбук 2, Proxmox)
        ├──► [Windows VDI — RDS Host]  ──── (Ноутбук 2, Proxmox)
        └──► [Docker-контейнер — code-server/терминал] (Ноутбук 3)
        
[HAProxy на FreeBSD] ──── балансировщик нагрузки (Ноутбук 1)
[NFS на FreeBSD]     ──── общее хранилище профилей (Ноутбук 1)
[Prometheus + Grafana] ── мониторинг всего (Ноутбук 3)
```

### 🔹 Ноутбук 1 — Router/Storage (Хафизов Айгиз)

**ОС:** FreeBSD 14 (установлена на голое железо)  
**Ресурсы:** Все 16 ГБ RAM / 512 ГБ SSD доступны FreeBSD напрямую  
**Физическая роль:** Шлюз всей сети + файловый сервер + балансировщик

**Что устанавливается и зачем:**

| Компонент            | Зачем                                                                             | Порт/Путь                                |
| -------------------- | --------------------------------------------------------------------------------- | ---------------------------------------- |
| `pf` (Packet Filter) | Firewall + NAT: все VDI-клиенты выходят в интернет через этот узел                | —                                        |
| `dummynet`           | Ограничение скорости каждого VDI-потока до 3–5 Мбит/с (чтобы не перегружать сеть) | —                                        |
| `HAProxy`            | Балансировщик: принимает RDP-подключения и распределяет по VDI-машинам            | `:3389`                                  |
| `NFS-сервер`         | Общее хранилище: ISO-образы, бэкапы Proxmox, домашние каталоги пользователей      | `/usr/local/iso`, `/backup`, `/home/vdi` |
| `Samba`              | Шара для Windows VDI — доступ к общим документам из Windows                       | `\\10.0.40.1\share`                      |
| `syslogd`            | Приём логов от всех узлов сети                                                    | `:514` UDP                               |

**Структура дискового пространства FreeBSD:**
```
/           — 20 ГБ (система)
/usr/local/iso  — 100 ГБ (ISO-образы для Proxmox)
/backup         — 200 ГБ (бэкапы ВМ через vzdump)
/srv/share      — 50 ГБ (Samba-шара)
/home/vdi       — 100 ГБ (роуминг профилей пользователей)
```

**Ключевые конфиги (лежат в репо):**
- `configs/freebsd/pf.conf` — правила firewall и NAT
- `configs/freebsd/dummynet.conf` — ограничение скорости
- `configs/freebsd/haproxy.cfg` — балансировка RDP
- `configs/freebsd/exports` — NFS-экспорты
- `configs/freebsd/smb.conf` — Samba

**Виртуальные машины на этом узле:**

**Шаблоны Proxmox:**
После настройки ВМ конвертируются в **шаблоны** (Templates) — это позволяет за 30 секунд создать клон для нового студента или при нагрузочном тесте.

**Сетевые мосты Proxmox:**
```
vmbr0 — LAN-мост (физическая сеть, VLAN 10/20)
vmbr1 — мост для Storage-трафика (VLAN 40, к FreeBSD NFS)
```

**NFS-монтирование (к FreeBSD):**
```
# В /etc/pve/storage.cfg добавить:
nfs: freebsd-nfs
    path /mnt/pve/freebsd-nfs
    server 10.0.40.1
    export /backup
    content backup,iso
```

**Ключевые конфиги (лежат в репо):**
- `configs/proxmox/network/interfaces` — конфиг мостов
- `configs/proxmox/vms/linux-vdi.conf` — конфиг ВМ
- `configs/proxmox/vms/windows-vdi.conf` — конфиг ВМ
- `configs/proxmox/storage.cfg` — подключение NFS

### Занятие 2 — FreeBSD: маршрутизатор и хранилище
**Исполнитель: Хафизов Айгиз (Ноутбук 1)**

**Задачи:**
1. Установить FreeBSD 14 на ноутбук 1 с официального ISO
2. Настроить сетевые интерфейсы (`/etc/rc.conf`):
   ```sh
   ifconfig_em0="inet 10.0.10.1 netmask 255.255.255.0"
   ifconfig_em1="inet 10.0.40.1 netmask 255.255.255.0"
   gateway_enable="YES"
   ```
3. Настроить `pf` — firewall и NAT (`/etc/pf.conf`):
   ```pf
   # NAT для всех VDI-клиентов
   nat on $ext_if from 10.0.0.0/16 to any -> ($ext_if)
   # Разрешить трафик между VLAN
   pass in on $int_if
   ```
4. Настроить `dummynet` — ограничение каждого VDI-потока до 4 Мбит/с:
   ```sh
   # Труба для каждого клиента
   ipfw pipe 1 config bw 4Mbit/s
   ipfw add pipe 1 ip from 10.0.20.0/24 to any
   ```
5. Настроить NFS-экспорт (`/etc/exports`):
   ```
   /backup  -alldirs -maproot=root  10.0.40.0/24
   /usr/local/iso  -ro  10.0.40.0/24
   /home/vdi  -alldirs -maproot=root  10.0.20.0/24
   ```
6. Настроить Samba (`/usr/local/etc/smb4.conf`) — шара `/srv/share`
7. Установить HAProxy (`pkg install haproxy`) — конфиг в следующем занятии

**Результат занятия:** FreeBSD — шлюз сети, NFS работает, Proxmox видит NFS как Storage.

### Занятие 4 — Балансировка и централизованные логи
**Исполнитель: Хафизов Айгиз (HAProxy на FreeBSD) + Василков Арсений (syslog в Docker)**

**Задачи Хафизова (FreeBSD):**
1. Настроить HAProxy для балансировки RDP (`/usr/local/etc/haproxy.cfg`):
   ```haproxy
   frontend rdp_front
       bind *:3389
       mode tcp
       default_backend rdp_back
   
   backend rdp_back
       mode tcp
       balance roundrobin
       server linux-vdi  10.0.20.10:3389 check
       server windows-vdi 10.0.20.11:3389 check
   ```
2. Настроить SSH Jump host на порту 2222:
   ```sh
   # В /etc/ssh/sshd_config добавить:
   Port 2222
   # Для проброса в Docker-контейнеры используем ProxyJump
   ```
3. Запустить `pflog` для записи всех соединений

**Задачи Василкова (Docker):**
1. Добавить `syslog-ng` в `docker-compose.yml`:
   ```yaml
   syslog:
     image: balabit/syslog-ng:latest
     ports:
       - "514:514/udp"
     volumes:
       - ./syslog-ng.conf:/etc/syslog-ng/syslog-ng.conf
       - syslog_data:/var/log/syslog-ng
   ```
2. Настроить FreeBSD, Proxmox и Ubuntu отправлять логи на `10.0.10.3:514`

**Гутник Вадим:**
- Имитировать отказ VDI (выключить ВМ в Proxmox) → проверить что HAProxy перенаправляет на второй сервер
- Засечь время переподключения

**Результат занятия:** HAProxy балансирует RDP, логи со всех узлов видны централизованно.

**Задачи:**

**Роуминг профилей Linux VDI:**
```bash
# На Linux VDI смонтировать NFS
echo "10.0.40.1:/home/vdi /home nfs defaults 0 0" >> /etc/fstab
mount -a
# Теперь /home находится на FreeBSD — одинаково на всех Linux VDI
```

**Роуминг профилей Windows VDI:**
```
# Групповая политика (если AD) или вручную:
# Свойства пользователя → Профиль → Путь к профилю:

```

**Автоматический logout через 15 мин (экономия RAM):**
```bash
# Linux VDI: добавить в /etc/profile.d/autologout.sh
TMOUT=900
readonly TMOUT
export TMOUT
```

**Проверка роуминга:**
1. Студент создаёт файл на `linux-vdi` → сохраняет в `/home/student01/test.txt`
2. Подключается к другому клону Linux VDI → файл должен быть виден
